## Part A — Additions to conventions (T10 appends A10–A17 to `docs/conventions.md`; binding for M2+)

### A10. Scoped permission model (plan §9, three layers in one `PermissionService`)
- `security.PermissionService` stays the single entry point; it must not depend on feature modules. T10 adds the SPI `security.ScopedPermissionResolver` (bean, implemented in `region.service.RegionPermissionResolver` in T11):
```java
public interface ScopedPermissionResolver {
  boolean isMember(UUID userId, UUID regionOrGroupId);
  boolean isAdmin(UUID userId, UUID regionOrGroupId);                 // ambassador of a region / admin of a group (one table region_admin, parity fs_botschafter)
  boolean isAdminOfAny(UUID userId);
  Set<UUID> adminOf(UUID userId); Set<UUID> memberOf(UUID userId);
  boolean hasFunctionGroupPermission(UUID userId, WorkingGroupFunction fn, UUID regionId); // ORGA → true; function group exists → its admins; else ambassadors of the region (upstream RegionPermissions::hasFunctionGroupPermissionForRegion)
  boolean hasRegionPermission(UUID userId, Permission p, UUID regionId); // region_permission row OR granted through a function (A10 table below)
  boolean mayAdministrateUser(UUID actorId, UUID userId);              // ORGA, or ambassador of any region the user is member of, or FSMANAGEMENT group admin of such a region (upstream CommonPermissions::mayAdministrateRegion)
}
```
- `PermissionService` new methods: `has(principal, Permission, regionId)` (ORGA → true; else resolver), `isAmbassador(principal, regionId)`, `isMemberOf`, `hasFunction(principal, fn, regionId)`, `mayAdministrateUser`, `requireXxx(...)` variants throwing 403 `ACCESS_DENIED`; `effectivePermissions(principal)` returns strings `"<PERMISSION>@<regionId>"` (ORGA: `"<PERMISSION>@*"`).
- Function → permission grants (plan §9 "can also be granted through a working-group function"), fixed table in `AppProperties.permissions.functionGrants`: `FSMANAGEMENT → CAN_MANAGE_USERS`, `WELCOME → CAN_GIVE_INTRO_PICKUPS`, `STORES_COORDINATION → CAN_USE_AUTOMATIONS, CAN_SEE_USER_PICKUP_COUNT_GROUPING, CAN_SEE_ALL_AUTOMATION_DECISIONS`, `REPORT → (none)`, `VOTING → CAN_MANAGE_SURVEYS`. Members (not only admins) of the function group get them.
- Who grants `region_permission`: ambassadors of the region and ORGA; `CAN_MANAGE_USERS` holders may grant `CAN_GIVE_INTRO_PICKUPS` only (reference AdminService.setTeacherAdmin / grantBookingUserAdmin generalised).
- Region types that accept members directly ("accessible"): `PART_OF_TOWN, CITY, REGION, DISTRICT` (upstream `UnitType::getAccessibleRegionTypes`). **Decision (deviates from upstream `mayJoinRegion` requiring FOODSAVER):** any signed-in user may join an accessible region, because journey step 2 happens as FOODSHARER.
- Frontend: `authGuard` `data: { permissions: Permission[], scope?: 'route:regionId' }` checks `SessionInfo.permissions` with `@<regionId>` or `@*`; `data.anyOf` semantics as reference routes (`CanManageUsers, CanGiveEinAbs`).

### A13. Seed date shifting (local profile only)
- `common.seed.SeedDateShiftContributor { void shift(Duration delta); }` SPI (T10). `dev.SeedDateShiftRunner` (`@Profile("local")`, `ApplicationRunner`, runs after Liquibase, once per start, guarded by table `seed_shift_state(last_shift_anchor)` so repeated starts shift by the remaining delta only): delta = `today(Europe/Zurich) − SEED_NOW.date`. In `e2e` the clock is fixed, so nothing shifts. M2 contributor: intro pickups (`start_at`, `booked_at`, `done_at`), quiz session end times (so hygiene expiry stays relative), passport issue dates. M3 adds pickups.

### A14. User-generated content in five languages
- Translatable rows use a sibling `<table>_i18n(owner_id, language VARCHAR(5), …text columns)` with `uq_<table>_i18n_owner_language`; reads fall back `requested → de → any`. Used by quizzes (question/answer/explanation), content pages, legal documents, learning chapters, region onboarding steps. Never JSON blobs for text (searchable, diffable).
- Seed translations for gws/fr/it are machine translations (decision 3); the `_i18n` CSVs are per language files `db/seed/<module>/<table>_i18n.csv`.

### A15. Time zones and "today"
- Every region carries `time_zone` (default `Europe/Zurich`). Services take `ZoneId` from the region of the entity (never a constant), via `RegionService.zoneOf(regionId)`; "same day" rules (CSV import day key, journey "today") use it. Frontend `RegionContextService` (T17) exposes the active region (route `:regionId`/`:slug`, else home region, else `Europe/Zurich`) and `fs-date` reads it.

### A16. Public endpoints and tags
- Public endpoints always live under `/api/public/<module>/…` with tag `public-<module>` and their own `Public<Module>Controller`; no SecurityConfig edits needed (M1 permits `/api/public/**`). Token-protected downloads (iCal feeds, unsubscribe) are public endpoints with 404 on unknown tokens (never 401).

### A17. Jobs and long-running work in M2
- `*Job` classes with `@Scheduled` + `@ConditionalOnProperty(app.scheduling.enabled)`; single instance assumed until ShedLock (M4). Long-running requests (batch passport PDF, CSV import) use `common.jobs.ProgressTracker` (in-memory, `jobId → {total, done, status, resultRef}`, 1 h TTL) exposed as `GET /api/jobs/{jobId}` (tag `jobs`, controller in `common.web`), the reused "progress bar" pattern of §14.1 (EA20).

## Part E — Risks to pre-empt
1. **Contract-before-code**: `OpenApiContractTest` fails if an `x-history` names a constant that does not exist — T10 must create every `<Module>Action` enum before writing the paths; workers may not rename constants.
2. **Hibernate validate with tables owned by other tasks**: entities and changelogs must land in the same task (hence the `bell` table moved into T10 as 019; `user_account` columns in T11 before any P-3 task).
3. **Closure table SQL portability**: `INSERT … SELECT` with self-join works on H2 PG-mode and Postgres; avoid recursive CTE differences. Test in `LiquibasePostgresIT` + unit test.
4. **Booking races**: `SELECT … FOR UPDATE` on the slot (reference) — H2 supports `PESSIMISTIC_WRITE`; cover with a two-thread IT (`IntroPickupBookingConcurrencyIT`).
5. **Quiz timing with fixed clock**: all age calculations via `Clock`; e2e advances the dev clock, the browser countdown must derive from `questionAgeSeconds` not `Date.now()`.
6. **PDF fonts/images in the jar**: embed Noto Sans and the logo as classpath resources; avatars are URLs → load from classpath fixtures in local/e2e, HTTP with timeout in prod, placeholder on failure.
7. **Apple/Google wallet dependencies** (BouncyCastle, google-auth) increase jar size and may conflict with Spring Security's Nimbus; keep them optional (`@ConditionalOnProperty`) and covered by unit tests with test certificates only.
8. **SSG with Optimus/zoneless**: prototype on `/` first (T22 day 1); fallback decision ready. Lighthouse in CI needs Chrome in the runner (use the Playwright image).
9. **Geocoding offline**: `StaticGeocodingClient` in local/e2e/test; Photon only in prod with circuit breaker; UI must show the "could not load suggestions — retry" compact state.
10. **Permission matrix drift**: every service checks via `PermissionService`; `PermissionServiceMatrixTest` is the contract; e2e R10 tests prove function groups supersede ambassadors.
11. **Seed date shift**: shifting only in `local` keeps e2e deterministic; verify twice-start idempotence in `SeedDateShiftIT`.
12. **Merge-order**: P-4 tasks need T17's shared components — never start P-4 from a branch without T17 merged; T22 must merge last (touches dashboard/landing/header/ci).
