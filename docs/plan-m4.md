## Part A — Conventions added in B1 (A23–A28, appended to `docs/conventions.md`)

**A23. Notification channels.** `NotificationService.notify` stays the single entry point. After the bell is stored it calls `notification.service.ChannelDispatcher` which fans out to `NotificationChannel` beans (`MailChannel` (existing outbox), `WebPushChannel`, `TelegramChannel`) filtered by `UserNotificationSettings` (per `NotificationCategory`, see below) and channel availability (push subscription present, Telegram linked). `NotificationType` gains `category()` → `NotificationCategory {STORE_TEAM, PICKUPS, PICKUP_REMINDER, AUTOMATION, INTRO_PICKUPS, REGION, ONBOARDING, FORUM, MESSAGES, SYSTEM}`; `SYSTEM` cannot be switched off. Mail is sent only when the request names a template (unchanged) **and** the category's mail flag is on; `pickup_reminders_enabled` (PU9) remains the master switch for `PICKUP_REMINDER` (both must be on). Channel failures are logged, counted in the integration registry (A26) and never fail the caller. Dev/e2e capture: `GET /api/dev/notifications` gains `channel ∈ {BELL, MAIL, PUSH, TELEGRAM}` (captured by `LogOnly*Transport`s in `local`/`e2e`).

**A24. Automation module.** `automation` depends on `store`, `pickup`, `region`, `user`, `notification`, `history`; `pickup`/`store` never depend on `automation`. Triggers are domain events published by `pickup`/`store` (`PickupSignedUpEvent(storeId, pickupAt, userId, confirmed, signedUpAt)`, `PickupSignedOutEvent(storeId, pickupAt, userId, byUserId, at)`, `PickupConfirmedEvent`, `StoreApplicationReceivedEvent(storeId, userId)`), consumed in `@TransactionalEventListener(AFTER_COMMIT)` + `REQUIRES_NEW` listeners (decision 33). The automation acts through public service methods added in B2 with an explicit automation actor: `PickupSignupService.confirmByAutomation(storeId, pickupAt, userId, policyName)`, `.removeByAutomation(…, message)`, `StoreTeamService.acceptByAutomation(storeId, userId)`, `.declineByAutomation(storeId, userId, message)`; history actor `AUTOMATION` with name `pickup-policy`/`request-policy`; messages to users go out as bell + mail (`PICKUP_AUTO_DECLINED`, `PICKUP_AUTO_CONFIRMED_WITH_MESSAGE`, `STORE_REQUEST_AUTO_DECLINED`) until M5 chat. Every decision is an audit row (`*_audit` tables) with `decision`, `reasons` (rule codes + rendered text), `userMessage`, `dryRun`; `DEFERRED` decisions write no audit (reference). Time zone for "calendar day" rules = `RegionService.zoneOf(store.regionId)`.

**A25. Jobs.** ShedLock (`shedlock-spring` + `shedlock-provider-jdbc-template` 6.x, table `shedlock`, `@EnableSchedulerLock(defaultLockAtMostFor = "PT30M")`). Every `*Job.run()` carries `@SchedulerLock(name = "<jobName>", lockAtLeastFor = "PT5S")`; ArchUnit rule 9: `@Scheduled` ⇒ `@SchedulerLock` with the same name as `jobName()`. `common.jobs.JobRunner.run(RunnableJob)` wraps every run (scheduled or manual): row in `job_run(job_name, started_at, finished_at, outcome OK|FAILED, message, trigger SCHEDULE|MANUAL, actor_id)`, log line, `IntegrationRegistry` touch. `runNow()` must be re-entrant (no lock; tests and ORGA "run now" bypass the lock). `GET /api/admin/jobs` / `POST /api/admin/jobs/{name}/run` (ORGA) expose the same list as `/api/dev/jobs`.

**A26. Integrations and circuit breakers.** `common.integration.IntegrationRegistry` holds one `CircuitBreaker` per `Integration {SMTP, WEB_PUSH, TELEGRAM, GEOCODING, HOLIDAY_CALENDAR, WALLET_APPLE, WALLET_GOOGLE, IMAP (M5, declared)}` — port of reference `FoodsharingAvailability`: `reportFailure(where, ex)` opens only when the failure "looks like an outage" (connect/read timeout, 5xx, unknown host) **and** a probe fails; `shouldSkip()` while open with `nextProbeAt` (probe interval `app.integrations.probe-interval=PT5M`); `markSucceeded()` closes; outage history 3 days (`outageOverlap/extendDeadline` used by the linked-store grace period). Clients (`SmtpMailTransport`, `WebPushClient`, `TelegramClient`, `GeocodingClient`, holiday loader) call through `registry.call(Integration, Supplier)`. Each client has `mode = live|log` (`app.<integration>.mode`); `local`/`e2e`/`test` use `log` (messages captured for `/api/dev/*`), prod `live`.

**A27. Mail polish.** `mail_outbox` gains `user_id`, `category` (NotificationCategory or `NEWSLETTER`/`AUTH`), `priority` (AUTH mails first), `rate_limited_until`. `MailRateLimiter`: per recipient `app.mail.rate-limit.per-user-per-hour=20` and per `(recipient, template)` `per-template-per-user-per-day=5`; beyond the limit mails are deferred (`rate_limited_until`), never dropped, except duplicates of the same template+identifier within 10 min, which are skipped (`MAIL_SUPPRESSED` history). All notification mails use `templates/mail/layout_<lang>.html` (logo, greeting, body fragment, footer with settings link and, for newsletters, the one-click unsubscribe link) and per-type fragments `templates/mail/notification/<TYPE>_<lang>.{html,txt}`; `MailTemplateService.render` falls back requested → de → en. `List-Unsubscribe` header on newsletters.

**A28. Telegram linking.** `user_account.telegram_chat_id`, `telegram_link_token(token, user_id, expires_at 15 min)`. User clicks "Connect Telegram" → `POST /api/telegram/link-token` → deep link `https://t.me/<bot>?start=<token>`. Incoming updates (`telegram-poll` job in `live` mode via `getUpdates`, or `POST /api/public/telegram/webhook/{secret}`; `e2e`/`local`: `POST /api/dev/telegram/incoming` simulates an update) with text `/start <token>` link the chat and answer with a confirmation message; `/stop` unlinks. Region/store alert chats: `telegram_chat(owner_type REGION|STORE, owner_id, chat_id, title, enabled)` chosen from `GET /api/telegram/chats` (chats seen in recent updates, reference `telegramChats()`); "Send test message" exists for both.

## Part F — Risks
1. **Event ordering**: automation listeners run AFTER_COMMIT + REQUIRES_NEW; the e2e "instant decision" assertion must poll the pickup state (≤ 2 s), not assume synchronous.
2. **Rule fidelity**: port the reference `evaluate()` line by line; `PickupPolicyEvaluatorTest` cases are derived from the reference branches (cleaning 4-way, linked-store defer/pending).
3. **Push in Playwright**: real Web Push cannot be delivered headless; tests assert captured pushes (`push.mode=log`) and the subscription round trip only.
4. **i18n volume**: ~60 bell types × 5 languages + mail fragments; B1 generates skeletons, F1/F7 review wording.
5. **ShedLock on H2**: `shedlock-provider-jdbc-template` works on H2 `MODE=PostgreSQL`; verify in `LocalProfileSmokeIT`.
6. **Module cycles**: `automation` must not be referenced by `pickup`/`store` (events + automation-actor service methods only); `ModulesTest` guards it.
7. **M3-F not merged**: F3/F4 ship standalone pages if `store-page`/region pages are missing (decision recorded).
