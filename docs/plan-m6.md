**A41. Images (C10).** `upload` gains `width, height, variants BOOLEAN, public BOOLEAN`. **A44. OAuth2/OIDC provider (C13), hand-written on `jose4j` (decision: no Spring Authorization Server; it fights the cookie-session filter and needs its own JDBC schema).** Framework-style endpoints outside `/api` (listed in `x-framework-endpoints`, excluded from SPA forwarding): `GET /oauth/authorize` (validates client/redirect/scope/PKCE, redirects to the Angular page `/oauth/consent?request=<id>` or, when a remembered consent exists, straight back with the code), `POST /oauth/token` (form-encoded, CSRF-exempt, `client_secret_basic`/`client_secret_post`, grants `authorization_code` + `refresh_token`, PKCE `S256` **required for public clients**, codes 10 min single-use), `GET|POST /oauth/userinfo` (Bearer JWT), `GET /.well-known/openid-configuration`, `GET /.well-known/jwks.json`. Access tokens RS256 JWT 1 h (claims `sub`=user uuid, `scope`, `client_id`, `iss`=`app.base-url`), refresh tokens opaque 30 days stored hashed, ID token when `openid`. Userinfo per `docs/en/oauth.md`: `sub, preferred_username (<displayName>#<foodsaverNumber>)`; `profile` → `name, given_name, family_name, picture, locale (de-CH…)`; `email` → `email, email_verified`; `regions` → `region_ids[]`, `region_ambassador[]` (direct admin). Region-restricted clients: user must be an active member of one `required_region_ids` else consent page shows 403 `OAUTH_REGION_REQUIRED`. Signing key `app.oauth.signing-key-pem` (env `OAUTH_SIGNING_KEY`; committed dev key for local/e2e/test like VAPID). Consent "remember" stores `oauth_consent(client, user, scopes)`; users revoke under `/account/connections`.

**A45. Search index (C5).** `search_index(kind USER|REGION|GROUP|STORE|THREAD|FSP|EVENT|POLL, entity_id, title VARCHAR(300), subtitle VARCHAR(300), text VARCHAR(4000) lower-cased + unaccented, region_id, visibility VARCHAR(40) PUBLIC|REGION_MEMBERS|FORUM|ADMINS, updated_at; uq(kind, entity_id))`, rebuilt nightly by `search-reindex` and incrementally by `SearchIndexer.upsert/remove` called from `@TransactionalEventListener` on existing domain events where they exist (store created/renamed, thread created/renamed, FSP, event, user name change); ILIKE `%term%` per term, `pg_trgm` GIN index in a `dbms: postgresql` changeset. Visibility is filtered per actor at query time (users: same region unless ORGA; stores/threads/polls/events: member regions; FSPs/regions/groups: everyone).

## Part F — Risks
1. **B1 size**: the M6 contract is the largest of all milestones. Two runs are pre-authorised; the F queue cannot start before B1 is complete, so B1 writes `profiles`/`users`/`calendar`/`uploads`/`baskets`/`food-share-points`/`map` first (unblocks F1–F3) and the rest second.
2. **Account deletion completeness**: a missed contributor leaves personal data behind. `AccountDeletionCoverageTest` (B14) scans every table with a `user_id`/`owner_id`/`*_user_id` column against the deleted id; every B task lists its contributor explicitly.
3. **Public uploads**: anonymous `GET /api/uploads/{id}` must only serve `public=true` rows; `UploadPublicAccessTest` + e2e checks that a mailbox attachment is still 403 for a visitor.
4. **OAuth security**: exact redirect matching, PKCE mandatory for public clients, single-use codes, hashed secrets/refresh tokens, `state`/`nonce` round-tripped; `OAuthFlowIT` covers the negative cases. The consent page is the only Angular route under `/oauth/`.
5. **Position privacy**: HOME baskets and user markers are rounded to 3 decimals; never expose exact home coordinates in markers or bubbles.
6. **Frontend host pages still unmerged (M3–M5)**: dashboard pickup cards, store team "report" button, bells deep links ship as links/standalone when the host is absent (decision carried over).
7. **Search performance**: trigram index only on Postgres; H2 (local/e2e) uses plain ILIKE, acceptable for seed volume; B14 verifies the Postgres plan.
8. **Images without a library**: ImageIO handles JPEG/PNG/GIF/WebP(read via plugin absent → WebP uploads stored without variants, flagged `variants=false`); EXIF orientation is normalised client-side because the crop re-encodes through a canvas.
