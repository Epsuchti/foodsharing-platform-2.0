# Decisions

Decisions taken during the build where plan.md was ambiguous. Closest to foodsharing.network behaviour unless noted.

| # | Date | Topic | Decision | Why |
|---|---|---|---|---|
| 1 | 2026-10-27 | §14 feature IDs | §14 rows get IDs `EA1..` (§14.1 rows in order), `AU1..` (§14.2 rows), `SV1` (§14.3), `AD1` (§14.4) so they can be tagged in Playwright like §13 IDs. | plan.md gives §14 no IDs, but the coverage script needs them. |
| 2 | 2026-10-27 | Fake OIDC provider | The `local` and `e2e` profiles include an embedded fake OIDC provider (`/dev/oidc/**`, bean only in those profiles) that Spring's `oauth2-client` uses as the "google" registration. No Docker container is needed, so `local` runs fully offline. | Plan §18.3 suggests mock-oauth2-server; the embedded one gives the same OIDC flow without a container and works offline. |
| 3 | 2026-10-27 | Human-only steps | Usability tests with real Zürich users (§11.5, §18.5 round 3, §20 M7), native-speaker translation review, production deploy, real load test on prod hardware are replaced during the build by AI persona walkthroughs (screenshots reviewed against the checklist per persona), automated load test (k6-style script against the local jar) and machine translations. They are listed in `docs/launch-report.md` as needing a human before launch. | They require people or infrastructure that do not exist yet (domain and hosting are open, plan §21). |
| 4 | 2026-10-27 | Error codes | `ApiErrorCode` exists only in `openapi/schemas/common.yaml`; Java and TS use the generated enums (`network.foodsharing.api.model.ApiErrorCode`). No hand-written copy (the reference had one). Added `NOT_IMPLEMENTED` (501, placeholder operations) and `ApiError.args` (interpolation values for `errors.<CODE>`). | One source; the i18n check parses the same list. |
| 5 | 2026-10-27 | Sessions | Server-side sessions in `auth_session` behind an HttpOnly `fs_session` cookie (SHA-256 of a 256-bit token stored), CSRF via `XSRF-TOKEN` cookie → `X-XSRF-TOKEN` header (token loaded on every request so the cookie is always present), instead of the reference's bearer token in localStorage. Sliding expiry is a bulk JPQL update (no optimistic-lock conflicts between parallel requests of one session). | Plan §8.2; one origin; no token readable by scripts. |
| 6 | 2026-10-27 | `@Tracked` listener | `TrackedFieldListener` (Hibernate `PostUpdateEventListener`) is registered through `hibernate.integrator_provider` from a Spring `HibernatePropertiesCustomizer`, not `META-INF/services`. It inserts its rows with JDBC on the session connection (persisting during a flush is not allowed). A field the transaction already recorded explicitly (`HistoryService.record` with `field`) is not recorded again as FIELD_CHANGED. Enum values are stored by constant name. | A ServiceLoader integrator would need a static bean holder, which breaks with several cached Spring test contexts. |
| 7 | 2026-10-27 | Liquibase contexts | Every profile sets `spring.liquibase.contexts` (`schema`; local/e2e `schema,seed`). `includeAll` was verified to work inside the packaged fat jar (Spring Boot nested jar), so the generated-master fallback of plan-m1 Part E is not needed. | Without a runtime context Liquibase runs all changesets, i.e. seed data would reach prod. |
| 8 | 2026-10-27 | Shared enums in entities | Entities use the generated `Role`, `Language`, `Theme` enums (`@Enumerated(STRING)`, stored by constant name, e.g. `GWS`, `STORE_MANAGER`); no separate `UserRole`. `Theme` joins the ArchUnit rule-3 exception list. | Avoids duplicate enums and mapping code for the same string sets. |
| 9 | 2026-10-27 | Module dependencies | The cookie filter uses the `security.SessionAuthenticator` interface implemented by `auth.service.AuthSessionService` (plan listed AuthSessionService under security). History actor names come from `history.ActorDirectory`, implemented by the user module (no history→user dependency). | Keeps the module graph acyclic for Spring Modulith. |
| 10 | 2026-10-27 | Spring Modulith | `spring-modulith` 2.0.9 resolves for Boot 4.0.9; no ArchUnit slice fallback. `config`, `security`, `common` and the generated `api` package (via a hand-written `package-info.java`) are OPEN modules; feature modules expose `service`, `domain` and `mapper` as named interfaces. | Generated models are used by every module; `HistoryMapper`/`AuthMapper` are reused by other modules' controllers. |
| 11 | 2026-10-27 | Node version | `frontend-maven-plugin` installs Node v24.15.0 / npm 11.12.1 (plan: 24.11.1/11.6.2). | Angular CLI 22.2 requires Node ^24.15.0. |
| 12 | 2026-10-27 | SPA forwarding | `/login` and `/login/**` are Angular routes; only `/login/oauth2/**`, `/login/webauthn`, `/oauth2/**`, `/webauthn/**`, `/dev/oidc/**`, `/h2-console/**`, `/api/**`, `/actuator/**` are never forwarded. | plan-m1 said "exclude login", which would break the deep link `/login/verify`. |
| 13 | 2026-10-27 | History access | ORGA may read every history; other roles need the subject type's `HistoryAccessRule` bean (no rule = closed). `GET /api/history` without subject type + id is ORGA only; CSV export ORGA only (max 10 000 rows). | Least privilege by default; modules opt in per subject type. |
| 14 | 2026-10-27 | Foodsaver number | `foodsaver_number_seq` starts at 200000; seed users use 100001–100099. | New local users never collide with seed numbers. |
| 15 | 2026-10-27 | `x-history` | Mutating operations that record nothing declare `x-history: NONE` (client error reports, dev seed reset, captured mails, dev clock). `OpenApiContractTest` checks every other value names an existing `<Action>.<CONSTANT>`. | The contract check requires x-history on every mutating operation. |
| 16 | 2026-10-27 | Java generator | `documentationProvider=none`, `annotationLibrary=none` in the spring generator (no springdoc/Swagger annotations or dependency). | The contract files are the documentation; springdoc 2.x does not support Boot 4. |
| 17 | 2026-10-27 | Google OIDC config | No `issuer-uri` property (Spring Boot would run OIDC discovery at startup); the expected issuer is `app.auth.google.issuer`. | A9: no discovery; the local issuer is the app itself. |
| 19 | 2026-10-27 | Dev seed reset on non-H2 | `POST /api/dev/seed/reset` answers 409 `NOT_IMPLEMENTED` on databases other than H2. | Reset uses `DROP ALL OBJECTS`, which is H2-only; dev endpoints never exist in prod anyway. |
| 20 | 2026-10-27 | Fake OIDC timestamps | The fake OIDC provider derives its issuer from the request and signs tokens with real time (`MutableClock.realInstant()`), while the app clock may be fixed (e2e). | Spring Security validates iat/exp against the system clock. |
| 21 | 2026-10-27 | Seed CSVs | Empty optional cells are written as `NULL`; seed changeset ids are `seed-NNN-n`. | Liquibase loads empty cells as empty strings, which breaks nullable timestamps. |
| 22 | 2026-10-27 | Mail transport SPI | `MailTransport.send(OutgoingMail)`; `CapturingMailTransport` (`app.mail.transport=capture`, e2e/test) and `SmtpMailTransport` (`smtp`). Mail history actions `MAIL_QUEUED/SENT/FAILED` on subject SYSTEM. | One outbox for every mail; e2e reads mails via `/api/dev/mails`. |
| 23 | 2026-10-27 | Passkey storage | `passkey_credential` stores `credential_type`, `attestation_object` and `attestation_client_data_json` (Spring re-reads them on login); `passkey_user_entity` has its own UUID id plus unique `user_id`. | Required by Spring Security WebAuthn's repositories; A6 id rule. |
| 24 | 2026-10-27 | Google issuer check | Issuer validated only against `app.auth.google.issuer` (Google's issuer also accepted without scheme). | Boot's built-in Google template would force accounts.google.com and break the local fake provider. |
| 25 | 2026-10-27 | Magic link privacy | Blocked domains get 400 even for existing accounts; rate limiting runs before the blocklist check; the request always answers 202 otherwise. | Never reveal whether an account exists. |
