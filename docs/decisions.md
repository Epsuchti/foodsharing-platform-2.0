# Decisions

Decisions taken during the build where plan.md was ambiguous. Closest to foodsharing.network behaviour unless noted.

| # | Date | Topic | Decision | Why |
|---|---|---|---|---|
| 1 | 2026-10-27 | §14 feature IDs | §14 rows get IDs `EA1..` (§14.1 rows in order), `AU1..` (§14.2 rows), `SV1` (§14.3), `AD1` (§14.4) so they can be tagged in Playwright like §13 IDs. | plan.md gives §14 no IDs, but the coverage script needs them. |
| 2 | 2026-10-27 | Fake OIDC provider | The `local` and `e2e` profiles include an embedded fake OIDC provider (`/dev/oidc/**`, bean only in those profiles) that Spring's `oauth2-client` uses as the "google" registration. No Docker container is needed, so `local` runs fully offline. | Plan §18.3 suggests mock-oauth2-server; the embedded one gives the same OIDC flow without a container and works offline. |
| 3 | 2026-10-27 | Human-only steps | Usability tests with real Zürich users (§11.5, §18.5 round 3, §20 M7), native-speaker translation review, production deploy, real load test on prod hardware are replaced during the build by AI persona walkthroughs (screenshots reviewed against the checklist per persona), automated load test (k6-style script against the local jar) and machine translations. They are listed in `docs/launch-report.md` as needing a human before launch. | They require people or infrastructure that do not exist yet (domain and hosting are open, plan §21). |
| 4 | 2026-10-27 | Error codes | `ApiErrorCode` exists only in `openapi/schemas/common.yaml`; Java and TS use the generated enums (`network.foodsharing.api.model.ApiErrorCode`). No hand-written copy (the reference had one). Added `NOT_IMPLEMENTED` (501, placeholder operations) and `ApiError.args` (interpolation values for `errors.<CODE>`). | One source; the i18n check parses the same list. |
| 5 | 2026-10-27 | Sessions | Server-side sessions in `auth_session` behind an HttpOnly `fs_session` cookie (SHA-256 of a 256-bit token stored), CSRF via `XSRF-TOKEN` cookie → `X-XSRF-TOKEN` header (token loaded on every request so the cookie is always present), instead of the reference's bearer token in localStorage. Sliding expiry is a bulk JPQL update (no optimistic-lock conflicts between parallel requests of one session). | Plan §8.2; one origin; no token readable by scripts. |
| 6 | 2026-10-27 | `@Tracked` listener | `TrackedFieldListener` (Hibernate `PostUpdateEventListener`) is registered through `hibernate.integrator_provider` from a Spring `HibernatePropertiesCustomizer`, not `META-INF/services`. It inserts its rows with JDBC on the session connection (persisting during a flush is not allowed). A field the transaction already recorded explicitly (`HistoryService.record` with `field`) is not recorded again as FIELD_CHANGED. Enum values are stored by constant name. | A ServiceLoader integrator would need a static bean holder, which breaks with several cached Spring test contexts. |
| 7 | 2026-10-27 | Liquibase contexts | Every profile sets `spring.liquibase.contexts` (`schema`; local/e2e `schema,seed`). `includeAll` was verified to work inside the packaged fat jar (Spring Boot nested jar), so the generated-master fallback of plan-m1 Part E is not needed. | Without a runtime context Liquibase runs all changesets, i.e. seed data would reach prod. |
| 8 | 2026-10-27 | Shared enums in entities | Entities use the generated `Role`, `Language`, `Theme` enums (`@Enumerated(STRING)`, stored by constant name, e.g. `GWS`, `STORE_MANAGER`); no separate `UserRole`. `Theme` joins the ArchUnit rule-3 exception list. | Avoids duplicate enums and mapping code for the same string sets. |
| 9 | 2026-10-27 | Module dependencies | The cookie filter uses the `security.SessionAuthenticator` interface implemented by `auth.service.AuthSessionService` (plan listed AuthSessionService under security). History actor names come from `history.ActorDirectory`, implemented by the user module (no history→user dependency). | Keeps the module graph acyclic for Spring Modulith. |
| 10 | 2026-10-27 | Spring Modulith | `spring-modulith` 2.0.9 resolves for Boot 4.0.9; no ArchUnit slice fallback. `config`, `security`, `common` and the generated `api` package (via a hand-written `package-info.java`) are OPEN modules; feature modules expose `service`, `domain` and `mapper` as named interfaces. | Generated models are used by every module; `HistoryMapper`/`AuthMapper` are reused by other modules' controllers. |
| 11 | 2026-10-27 | Node version | `frontend-maven-plugin` installs Node v24.15.0 / npm 11.12.1 (plan: 24.11.1/11.6.2). | Angular CLI 22.2 requires Node ^24.15.0. |
| 12 | 2026-10-27 | SPA forwarding | `/login` and `/login/**` are Angular routes; only `/login/oauth2/**`, `/login/webauthn`, `/oauth2/**`, `/webauthn/**`, `/dev/oidc/**`, `/h2-console/**`, `/api/**`, `/actuator/**` are never forwarded. | plan-m1 said "exclude login", which would break the deep link `/login/verify`. |
| 13 | 2026-10-27 | History access | ORGA may read every history; other roles need the subject type's `HistoryAccessRule` bean (no rule = closed). `GET /api/history` without subject type + id is ORGA only; CSV export ORGA only (max 10 000 rows). | Least privilege by default; modules opt in per subject type. |
| 14 | 2026-10-27 | Foodsaver number | `foodsaver_number_seq` starts at 200000; seed users use 100001–100099. | New local users never collide with seed numbers. |
| 15 | 2026-10-27 | `x-history` | Mutating operations that record nothing declare `x-history: NONE` (client error reports, dev seed reset, captured mails, dev clock). `OpenApiContractTest` checks every other value names an existing `<Action>.<CONSTANT>`. | The contract check requires x-history on every mutating operation. |
| 16 | 2026-10-27 | Java generator | `documentationProvider=none`, `annotationLibrary=none` in the spring generator (no springdoc/Swagger annotations or dependency). | The contract files are the documentation; springdoc 2.x does not support Boot 4. |
| 17 | 2026-10-27 | Google OIDC config | No `issuer-uri` property (Spring Boot would run OIDC discovery at startup); the expected issuer is `app.auth.google.issuer`. | A9: no discovery; the local issuer is the app itself. |
| 19 | 2026-10-27 | Dev seed reset on non-H2 | `POST /api/dev/seed/reset` answers 409 `NOT_IMPLEMENTED` on databases other than H2. | Reset uses `DROP ALL OBJECTS`, which is H2-only; dev endpoints never exist in prod anyway. |
| 20 | 2026-10-27 | Fake OIDC timestamps | The fake OIDC provider derives its issuer from the request and signs tokens with real time (`MutableClock.realInstant()`), while the app clock may be fixed (e2e). | Spring Security validates iat/exp against the system clock. |
| 21 | 2026-10-27 | Seed CSVs | Empty optional cells are written as `NULL`; seed changeset ids are `seed-NNN-n`. | Liquibase loads empty cells as empty strings, which breaks nullable timestamps. |
| 22 | 2026-10-27 | Mail transport SPI | `MailTransport.send(OutgoingMail)`; `CapturingMailTransport` (`app.mail.transport=capture`, e2e/test) and `SmtpMailTransport` (`smtp`). Mail history actions `MAIL_QUEUED/SENT/FAILED` on subject SYSTEM. | One outbox for every mail; e2e reads mails via `/api/dev/mails`. |
| 23 | 2026-10-27 | Passkey storage | `passkey_credential` stores `credential_type`, `attestation_object` and `attestation_client_data_json` (Spring re-reads them on login); `passkey_user_entity` has its own UUID id plus unique `user_id`. | Required by Spring Security WebAuthn's repositories; A6 id rule. |
| 24 | 2026-10-27 | Google issuer check | Issuer validated only against `app.auth.google.issuer` (Google's issuer also accepted without scheme). | Boot's built-in Google template would force accounts.google.com and break the local fake provider. |
| 25 | 2026-10-27 | Magic link privacy | Blocked domains get 400 even for existing accounts; rate limiting runs before the blocklist check; the request always answers 202 otherwise. | Never reveal whether an account exists. |
| 26 | 2026-10-27 | Zürich Stadt type | `zuerich-stadt` is CITY (not BIG_CITY) so members can join it directly; Berlin/Hamburg/Wien stay BIG_CITY. | Upstream forbids joining BIG_CITY directly; R2 needs newcomers to join Zürich Stadt. |
| 27 | 2026-10-27 | Seed memberships | `newbie@local` and `profile@local` have no region yet (their journey stage); the other 12 seed users are members of Zürich Stadt and ancestors. | Matches their onboarding stage. |
| 28 | 2026-10-27 | Region admin rights | "Ambassador of region X" includes ambassadors of ancestor regions and admins of X's FS-management group; ORGA handled centrally in `PermissionService`; `WorkingGroupFunction` lives in `security` to avoid a cycle. | Upstream `mayAdministrateRegion` with parent regions. |
| 29 | 2026-10-27 | Leaving home region | Allowed only when another joinable membership exists (it becomes the home region); else 409 `CANNOT_LEAVE_HOME_REGION`. | Every foodsaver needs a home region. |
| 30 | 2026-10-27 | Contract shape M2 | Public endpoints of a module get their own tag file (`public-content`, `public-legal`, …); wallets split into `/wallets/apple` (pkpass) and `/wallets/google` (link); job downloads in tag `jobs`; guide iCal feed `/api/public/intro-pickups/ical/{token}`. | One tag per controller/file. |
| 31 | 2026-10-27 | Geocoding | Provider chosen by `app.geocoding.provider` (`static` offline table in local/e2e/test, `photon` in prod). | Local runs offline. |
| 32 | 2026-10-27 | Profile history | Own and admin profile edits share one model; history per field (PROFILE_UPDATED, PROFILE_UPDATED_BY_ADMIN with required reason, PHONE_CHANGED, HOME_REGION_CHANGED); phone and birth date recorded as `***`; phones stored E.164 (default CH). | Privacy; §10 profile change history. |
| 33 | 2026-10-27 | After-commit listeners | `@TransactionalEventListener(AFTER_COMMIT)` handlers that write use `REQUIRES_NEW`. | Otherwise their writes are never committed. |
| 34 | 2026-10-27 | Id-token clock | `AuthLoginConfig` validates id-token iat/exp against `MutableClock.realClock()` (real time), not the application clock that e2e fixes at SEED_NOW; the fake OIDC provider signs with real time like Google. | With the fixed e2e clock every Google login failed with "Jwt expired". |
| 35 | 2026-10-27 | Passkey nudge & login flow (T6) | "Log in faster next time" card after Google/magic-link logins (not passkey/dev), once per device (`localStorage['fs.passkeyNudge']`; `sessionStorage['fs.loginPending']` carries it across the Google redirect). Passkey login offers autofill (conditional mediation) plus a button. Security log is a feature-local list (the endpoint only pages; no filters for `fs-history-timeline`). | Plan §8.1; keeps the login page one-primary-action. |
| 36 | 2026-10-28 | Seed quiz pool | 12 FOODSAVER questions and 5 per other quiz in seed (not 7×20); editors add more via the quiz editor. | Enough to exercise all rules in tests; content is editorial. |
| 37 | 2026-10-28 | Working groups | Group creators become group admins; applying to a group requires membership of its parent region (`NOT_A_MEMBER`). | Matches foodsharing. |
| 38 | 2026-10-28 | Content editors | ORGA or admins of a PR-function group (any region) may edit content pages. | Upstream PR/Content permissions. |
| 39 | 2026-10-28 | Enum query params | Bound by JSON value (`ApiEnumConverterConfig`); mail subjects support `{var}` placeholders. | Generated enums use JSON values on the wire. |
| 40 | 2026-10-28 | EinAb rules | Delete = soft delete (`deleted_at`), free places cancelled; partial updates; "counted" = DONE or BOOKED after start; minimum pickup count counts DONE only; enabling a guide grants `CAN_GIVE_INTRO_PICKUPS`. | Reference app behaviour. |
| 41 | 2026-10-28 | EinAb CSV import | Unknown foodsaver number → `UNKNOWN_USER` row (no placeholder accounts); non-member → `USER_OTHER_REGION`; store aliases per region; progress via job tracker. Booking mails link the `.ics` (no attachments in the outbox). | Reference import with our data model. |
| 42 | 2026-10-28 | Passports | Valid 3 years from start; reprint keeps validity, renew starts today; Helvetica + grey photo placeholder; batch PDF is a job result. Layout spec in `docs/passport-layout.md` + sample PNG for admin approval. Wallets answer 503 `WALLET_NOT_CONFIGURED` until signing keys are configured. | Plan §21 #5; wallet keys need the domain. |
| 43 | 2026-10-28 | Verification readiness | "Learning done" is derived from quiz role / passed quiz until learning-page tracking exists (T22). | Avoids a fake flag. |
| 44 | 2026-10-28 | Journey rules | Verified users' open region extra steps count as done; PROFILE_REGION needs first/last name, valid mobile and home region; LEARN is DONE+optional when the region doesn't require learning pages; QUIZ done when role or quiz role ≥ FOODSAVER. Replaces #43: `learningDone` comes from real learning progress. | §11.1 with existing foodsavers never blocked. |
| 45 | 2026-10-28 | Onboarding nudges | Stalled = active unverified, journey incomplete, no progress 30 days (registration, chapters, step confirmations, quiz pass, EinAb activity), not waiting for others; max one per 30 days (`onboarding_nudge`). "Step unblocked" bells only when the resolved step is DONE. New bookable EinAbs reuse T15's `INTRO_PICKUP_NEW_BOOKABLE`. | §11.3 nudges without spam. |
| 46 | 2026-10-28 | Explainer counters | Counters come from per-module beans in the onboarding module's SPI (no dependency cycle); stores/pickups/kg contribute from M3. | Modulith boundaries. |
| 47 | 2026-10-28 | M3 contract paths | Pickups addressed by `{pickupAt}` (ISO date-time); pickup history at `/api/stores/{id}/pickup-history` (path collision); `cancelMyStoreApplication` (unique operationIds); category/grocery history on subject SYSTEM. | Generator/route constraints. |
| 48 | 2026-10-28 | SPI defaults | Default SPI implementations are plain beans, real ones are `@Primary` (no `@ConditionalOnMissingBean` outside auto-config). | Order-independent wiring. |
| 49 | 2026-10-28 | Store schema | `store_grocery`, `store_chain_kam` have own UUID id + unique key; `pickup_weight_category` lives in the store module (seed range 0021-0004). | A6 id rule; store must not depend on pickup. |
| 50 | 2026-10-28 | Store permissions | Store coordination = ORGA, else admins of the region's STORES_COORDINATION group if one exists, else ambassadors of the region/ancestors. Removing a member needs a message; leaving yourself does not; max 3 / min 1 managers (coordinators exempt). | Upstream StorePermissions + docs/en/permissions/store.md. |
| 51 | 2026-10-28 | Pickup concurrency | Sign-ups and pickup edits serialise on a row lock of the store. | One lock covers regular + one-time pickups of a store. |
| 52 | 2026-10-28 | Upstream conflicts | Where upstream permission docs contradict upstream code, code wins (unverified team members read the wall; jumper chat = managers + jumpers). | Code is the live behaviour. |
| 53 | 2026-10-28 | Pickup rules | `editPickup` on a time without occurrence creates a one-time pickup; region pickup rule: limits ≤ 0 = unlimited, only same-region stores using the rule count, past sign-ups count; a full pickup the user is in reports only `ALREADY_SIGNED_UP`; pickup history defaults to 30 days; agenda in the home region's time zone; PICKUP history subject = store id. Seed has 93 past sign-ups (14 seed users) instead of ~650. | Upstream PickupRestController semantics. |
| 54 | 2026-10-28 | Store wall & delete | Wall delete: ORGA anything, authors own posts, managers/coordinators posts older than 30 days, always only for wall readers; deleted posts soft-deleted. Store delete = soft delete (wall too), 409 `STORE_HAS_PICKUPS` if the store ever had a sign-up. | Upstream wall permission table. |
| 55 | 2026-10-28 | Chains & categories | Chain admins = ORGA or STORE_CHAINS group admins; KAMs edit their chain but not the KAM list; KAMs must be active, verified, ≥ STORE_MANAGER. Categories/groceries ORGA-only, merge moves references then deletes the source. | Upstream StoreChainPermissions. |
